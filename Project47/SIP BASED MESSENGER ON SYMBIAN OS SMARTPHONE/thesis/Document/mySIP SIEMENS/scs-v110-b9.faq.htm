Answers

  1. Why is the video picture cropped at the borders?

    Answer:
    This is caused by faulty Windows drivers of the video camera, mainly of video cameras with a native CCD/CMOS sensor resolution that is not (Q)CIF but (Q)VGA. These faulty drivers do not interpolate (downsample) the VGA sensor data to CIF but instead just crop the borders and provide the application (in this case the SCS-Client) with the center portion of the VGA picture only.

    Solution (workaround):
    Configure the SCS-Client to not ask the video camera driver for the (Q)CIF resolution but the (Q)VGA instead and let the SCS-Clientdo the interpolation itself. Go to the configuration dialog, to the page "Audio & Video" and select either "CIF interpolated" or "QCIF interpolated" under "Video settings" -> "Size"

  2. Why is changing the video configuration disabled?

    Answer:
    The video settings controls are automatically greyed out when either the "My Video Camera" Box is open or at least one "Connection" Box has an active video connection.

    Solution:
    Close the "My Video Camera" Box and all video connections.

  3. Why don't the boxes snap to the Main-Bar even though I've configured them to do so?

    Answer:
    This is caused by a well known bug. The SCS-Client box snapping does not work if the Windows display properties "Show window contents while dragging" (under Start -> Settings -> Control Panel -> Display -> Effects) is not enabled.

    Solution:
    Enable the "Show window contents while dragging" setting.

  4. Where is the SCS-Client configuration stored?

    Answer:
    The SCS-Client stores its configuration in two XML files. These are located in the directory "C:\Documents and Settings\USERNAME\Application Data\Siemens\ScsClient" (of course the drive and/or directory names change depending on the type and language of the installation).

    Note 1:
    Every Windows user has a complete private configuration.

    Note 2:
    These XML files are synchronized with Window domain servers (if one is used and configured to do so) and therefore also available on other PCs in the same domain when using the same Windows login.

  5. Does the SCS-Client also use the Windows Registry?

    Answer:
    The SCS-Client neither reads from nor writes to the Windows Registry.

  6. When uninstalling and then re-installing the SCS-Client, the configuration settings do not get reset.

    Cause:
    The configuration XML files are not deleted during uninstallation. This is by design and not a bug. You can delete these files manually if you want to reset the configuration for a specific user.

    Workaround 1:
    You can delete these files manually if you want to. This does not cause any problems (apart from the user configuration being lost of course).

    Workaround 2:
    You can delete these files using the unofficial "SCSClientConfigReset.exe" tool. You can find this tool in the SCS-Client installation directory (usually "C:\Program Files\SCS-Client\SCSClientConfigReset.exe").

  7. How can I configure the tracer?

    Answer:
    The tracer can only be configured by editing the "user-config.xml" configuration file. Edit the section under <tracers> and read the "default-config.xml" for basic documentation.

  8. Where is the trace file?

    Answer:
    If you don't give a path in the "file" field in the file tracer configuration (<tracers><tracer><file>), the trace file is automatically placed in either the %TEMP% or %TMP% directory and the file name is automatically prefixed with the current users Windows login name.

  9. How can I start/stop the tracer?

    Answer:
    Starting and stopping the tracer is available from the enhanced Main-Bar menu which is shown if Shift+Ctrl is pressed (on the keyboard) together with the right mouse button.

  10. Why does the SCS-Client bind to "127.0.0.1".

    Answer:
    There are two possible reasons:

    1) Your PC does not have any IP address configured. In this case, the SCS-Client uses the "127.0.0.1" IP address as fallback. Note that "127.0.0.1" is also used if you have installed the "Microsoft Loopback Adapter" as your only network device. You can open a command prompt and type in "ipconfig /all" to see if which IP addresses and network cards you have configured.

    2) You have configured the SCS-Client to bind to "127.0.0.1" explicitly. Check and change this in the configuration dialog page "IP address".

  11. Do I need to have administrative privileges to install the SCS-Client?

    Answer:
    Yes. Our software protection mechanism requires this. Even if you managed to install the SCS-Clientwithout having administrative privileges, it will not run after such an installation.

  12. Do I need to install the SCS-Client on a local hard-disk?

    Answer:
    Yes. Our software protection mechanism requires this. You cannot install the SCS-Client on a network drive.

  13. Do I need to have "file create" and "file write" privileges for the SCS-Client installation directory?

    Answer:
    Yes. Our software protection mechanism requires this.

  14. What data does the SCS-Client software protection mechanism transmit via the Internet and via Email?

    Answer:
    When you request an SCS-Client licence via the licence wizard, only the data that you enter yourself into the wizard is transmitted, together with your random SCS-Clientsite code. This site code is an unreversible hash code of your computer's hardware configuration.

    Note:
    When you create a trial licence, nothing at all is transmitted via the Internet. The trial licence is created locally on your computer.

  15. I cannot create a trial licence after my first trial licence has expired.

    Answer:
    You can only create an SCS-Client trial licence once on every computer. After your first SCS-Client trial licence has expired, you need to buy a real licence.

    Note:
    Re-installing the SCS-Client does not enable you to create another trial licence. Re-installing Windows does not enable you to create another trial licence. Reformatting all your hard-drives does not enable you to create another trial licence. So don't try, it's just a waste of time.

  16. Is my SCS-Client licence deleted when I uninstall it?

    Answer:
    The SCS-Client uninstaller does not delete the SCS-Client licence. The SCS-Client uninstaller will not delete some directories and files on your computer. However, if you delete these directories or files manually, you will also lose your SCS-Client licence.

  17. Is my SCS-Client licence deleted if I install a newer version of the SCS-Client?

    Answer:
    If you install a newer version of the SCS-Client over an older version using the procedures described below, you will not lose your SCS-Client unless you delete directories or files manually.

    Instructions:
    1) Uninstall the old version of the SCS-Clientusing either the uninstall link in the Windows Start Menu or from the Add/Remove Programs Control Panel application.
    2) Reboot your PC immediately.
    3) Install the newer version of the SCS-Clientinto exactly the same directory where the old version has been installed before.

  18. How can I delete my SCS-Client licence?

    Answer:
    This is available from the licence info dialog if Shift+Ctrl is pressed while performing a double click on the image with the right mouse button. A confirmation dialog will be shown.

  19. What is the difference between the three versions of SCS-Client?

    Answer:
    Their feature set is different.

    The "Basic" version has only the basic feature set.

    The "Advanced" version has all the features of the "Basic" version plus secure-chat and secure-file-transfer via TLS.

    The "Professional" version has all the features of the "Advanced" version plus CIF video and flexible configuration of video bandwidth between 32 and 400 kBit/s (the other versions always use 350 kBit/s).

  20. Does my network infrastructure work with the SCS-Client?

    Answer:
    If your PC is using a public IP address, the SCS-Client should work (you also need to check if you are using a firewall, see below). This is usually the case with the simplest home network infrastructure, where the home user is using a modem (with no other network device) like a PSTN/ISDN/cable/ADSL modem to connect to the internet. You can test if your PC is using a public IP address through the following steps:
    1) connect your PC to the internet
    2) select "Run..." from the Windows Start menu
    3) type in "cmd /k ipconfig /all" (without the quotes), click "OK"
    4) a command window should open an show some information
    5) look for lines (maybe more than one) that start with "IP Address. ." and look at the number at the end of the line
    6) if one of these numbers do NOT match the following patterns, you use at least one public number:
            127.0.0.1 (loopback address)
            10.*.*.* (RFC 1918 class A private address range)
            172.x.*.* (RFC 1918 class B private address ranges, where x=16..31)
            192.168.*.* (RFC 1918 class C private address ranges)

    Private IP addresses:
    If you are using a private IP address and are connected to the internet through one or many NAT router(s) (like an ADSL router), SIP and so the SCS-Client will generally not work without specific changes. First, all your NAT routers must either be SIP capable or support UPnP. NAT routers that do support neither can technically not be used with SIP. See below for more details about using SIP with NAT routers.

    Firewalls:
    If you are using a firewall (either a personal firewall or a hardware firewall), you need to configure this firewall (or all firwalls if
    there is more than one) to allow SIP network traffic. See below for more details about configuring a firewall for SIP.

  21. Does the SCS-Client work with NAT? (network address translation)?

    Why is NAT needed?
    Each network endpoint (computer) needs a unique IP address for communicating over the internet. Because there are not that many IP addresses to begin with, and they also have not been assigned very smart, the world seems to run out of available IP addresses. NAT has been designed to solve this problem (among others).

    How does NAT work?
    There are three small ranges of IP addresses (for example 192.168.*.*) that are called private IP addresses. No network endpoint that is connected to the internet is allowed to use these private IP addresses. All other IP addresses are called public IP addresses. Private IP addresses can only be used in private networks (LANs). To connect such a private LAN to the public internet, a NAT router is needed. The NAT router has two network interfaces, one connected to the public internet and one connected to the private LAN. The public interface gets a public IP address while the private interface gets a private IP address assigned.
    For network traffic (messages) from the private LAN, the NAT router replaces the private source IP address with its own public IP address and forwards the message to the public internet, remembers this mapping and so can route a reply from the public internet back to the original message source on the private LAN.

    What is the issue with NAT?
    Even when using a NAT router to connect to the public internet, the network endpoints on the private LAN are not directly visible from the public internet. No network endpoint on the public internet can send anything to a computer on the private LAN, because these have no public IP address to send messages to. Note that this has also big security advantages.

    NAT and home users?
    NAT is used by most companies these days. But it's more and more often also used in home networks, often even without the home users explicitly knowing about it. For example, do all ADSL routers use NAT.

    How does this affect SIP and the SCS-Client?
    Like many other IP based protocols, SIP has big problems with NAT. And because SIP is an open IETF standard, no vendor can (or at least none should) solve the NAT issues of SIP on their own. What does that mean for users of the SCS-Client? It means that if your PC is behind a NAT (router), you cannot talk to any SCS-Client user on the other side of your NAT router. If you are a home user and you are connected to the internet via a NAT router, it means you cannot use the SCS-Client at all.

    Solutions:
    Today, there are two possible solutions:
    1) UPnP (Universal Plug & Play): through UPnP, the SCS-Client could talk to your NAT router and solve the SIP-NAT issue. v1.10 of the SCS-Client will implement UPnP.
    2) SIP (RFC3261) capable NAT routers: if your NAT router "supports" SIP (is a SIP (RFC3261) application layer gateway), you'll have no problems and the SCS-Client will work fine.

    Solutions for more than one NAT router:
    UPnP solves NAT for SIP only for the NAT router closest to your PC. All
    other NAT routers must directly support SIP.

  22. Does the SCS-Client work with firewalls?

    What is the problem (1)?
    Firewall block most IP traffic. If a firewall is not configured to let SIP traffic pass through, firewalls will block SIP.

    What is the problem (2)?
    As an additional security mechanism, firewalls often also do NAT. See comments above about NAT.

    Solution:
    If your (hardware or software) firewall knows SIP, you'll have no problem at all.

    Solution for hardware based firewalls that do not know SIP:
    If you use a hardware based firewall that does not know SIP, you must configure it to let SIP pass through. You'll need to open these protocols/ports for the SCS-Client:
    - port 5060 in both directions for all IPs for UDP (SIP)
    - ports 5060 and 5061 in both directions for all IPs for TCP (SIP)
    - ports 4500 through 4599 in both directions for all IPs for UDP and TCP (audio, video, chat)

    Solution for software based firewalls (personal firewalls) that do not know SIP:
    If you use a personal firewall that does not know SIP, you must configure it to let SIP pass through. Usually this is simpler than
    configuring hardware based firewalls. Simply configure your personal firewall to allow UDP and TCP traffic for all ports for all IPs for the SCS-Client application (SCSC.EXE).

  23. Can the SCS-Client been started more than once?

    Answer:
    Generally not. You can force the SCS-Client to start more than once by using the command line argument "/multistart".

  24. How can I display the SIP message log dialog?

    Answer:
    The SIP message log dialog is available from the enhanced Main-Bar menu which is shown if Shift+Ctrl is pressed (on the keyboard) together with the right mouse button.

  25. How can I force the SCS-Client to re-register at the SIP registrar?

    Answer:
    Re-Registering at SIP registrar is available from the enhanced "My SIP URL" menu (in the "My Contacts" Box) which is shown if Shift+Ctrl is pressed (on the
    keyboard) together with the right/left mouse button.

  26. How can I send DTMF characters?

    Answer:
    Select the SIP-URL of remote party in the "Connection" Box while audio is active (means both connected and neither on hold nor on mute), then press the DTMF key on the keyboard (0-9, a-d, *, #). You'll get textual feedback in the history when the DTMF character has been sent (no audio feedback is provided on the local machine).

  27. How can I edit/configure the "Shared Contacts"?

    Answer:
    This feature can only be configured by editing the "user-config.xml" configuration file. Edit the section under <buddyList><centralBuddyListFile>.

  28. How can I change the available font zoom values in the "Connection" box?

    Answer:
    This feature can only be configured by editing the "user-config.xml" configuration file. Edit the section under <gui><communicationBoxZoom><availableZoom>.

  29. How can I prevent the SCS-Client from clearing the chat history when I close the "Connection" box?

    Answer:
    This feature can only be configured by editing the "user-config.xml" configuration file. Edit the section under <gui><clearHistoryOnBoxClose>.

  30. How can I register more than one SIP URL?

    Answer:
    This feature can only be configured by editing the "user-config.xml" configuration file. Edit the section under <sipAccount><additionalSipUrls>.

  31. How can I configure the Ringer (for incoming calls) to play a different wave-file or use the beeper-device instead of the sound card?

    Answer:
    This feature can only be configured by editing the "user-config.xml" configuration file. Edit the section under <gui><ringer> and it's sub-keys.
