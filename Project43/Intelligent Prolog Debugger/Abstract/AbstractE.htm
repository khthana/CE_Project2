ABSTRACT

Program debugging can be divided into 2 stages: Program Diagnosis and Program Correction. This thesis explains the theory and the process of debugger construction in the diagnosis stage. The debugger that we have developed is semi-automatic and works interactively with the user like an assistant that helps finding the bug. We choose to use Prolog as an implementation language because it facilitates in meta-programming and being an interpreter makes the construction more convenient, especially if the target language is Prolog or other similar languages.

We use Algorithmic Program Debugging technique in our debugger. This technique is dynamic, that is, it uses the execution traces of the incorrect program to locate the bug. An interesting feature of this technique is the way it gathers the knowledge from the user. By asking only yes/no questions, this can make the debugger very easy to use.

For the debugger to be automatic, we must improve it so that the number of queries they pose is minimal. This is called Query Minimization. Even though this technique doesn't require the user to write the specification of the program, we have found that having the specification is another way of reducing the number of queries. This is because the debugger can consult the specification before asking the user.
